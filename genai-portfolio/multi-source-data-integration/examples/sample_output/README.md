# Sample Output - Multi-Source Data Integration

This directory contains representative example output from the four
example scripts in `examples/`. Reviewers can read these files to
understand what the integration pipeline produces without running any
code.

## Files

| File | Source script | What it shows |
| --- | --- | --- |
| `discovery_report.json` | `examples/run_discovery.py` | Source profiling for two heterogeneous systems (Oracle ERP, SQL Server CRM). Includes per-table row counts and column profiles, composite quality scores with weakest-column drill-down, schema-comparison coverage to the target warehouse, and dependency-aware parallel load waves. |
| `identity_resolution_results.json` | `examples/run_identity_resolution.py` | A 1,000-record customer reconciliation across the two sources. Shows matching strategies (exact, jaro-winkler, levenshtein, metaphone) with weights, survivorship rules with field-level overrides, sample resolved entities including a fuzzy match (`david lee` <-> `david lei`), and a human-review queue example. |
| `reconciliation_report.html` | `examples/run_reconciliation.py` (auto-generated) | Browser-renderable report covering count, value, and hash reconciliation across four entities (customer, product, sales_order, sales_order_line). Open in any browser. |
| `reconciliation_report.json` | `examples/run_reconciliation.py` (auto-generated) | Structured equivalent of the HTML report - the format consumed by downstream alerting and audit pipelines. |
| `pipeline_run_summary.txt` | `examples/run_full_pipeline.py` | End-to-end run summary across all five phases (discovery -> mapping -> identity resolution -> cutover -> reconciliation) with timings, row counts, and pass/fail status per phase. |

## Reading Order

1. `discovery_report.json` - what the integration sees in the source systems.
2. `identity_resolution_results.json` - how the same customer in two
   systems gets merged into one canonical record.
3. `reconciliation_report.json` - the post-cutover validation surface.
4. `reconciliation_report.html` - the human-friendly view of the same data.
5. `pipeline_run_summary.txt` - everything end-to-end with timings.

## Reproducing

```bash
./quickstart.sh
```

The quickstart script installs dependencies, runs the four example
scripts, and writes captured output into `output/quickstart/`. Compare
the live output against these reference samples for a smoke test.

## Notes

- All source data is synthetic, generated by the
  `legacy_oracle` and `legacy_sqlserver` adapters in `src/sources/`.
- The reconciliation run intentionally has one failing check
  (`product.total_list_price`) so the report shows both PASS and FAIL
  rendering paths.
- Timestamps in JSON are illustrative - real runs will have current
  timestamps.
- The HTML report is the actual file produced by `ReportGenerator` -
  it includes inline CSS and renders identically offline.
